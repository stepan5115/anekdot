# Контекст проекта «Смехдер»

Этот файл предназначен для продолжения работы в новой сессии. Достаточная команда для продолжения:

> Продолжи работу над проектом. Все вводные и текущее состояние описаны в `PROJECT_CONTEXT.md`.

## 1. Исходное задание

Полное техническое задание лабораторной находится в файле [`TZ_lab_crud.md`](./TZ_lab_crud.md).

Основные требования из него:

- веб-приложение должно состоять из REST API и клиентской части;
- требуется одна основная сущность как минимум с четырьмя полями разных типов;
- данные обязательно хранятся в базе данных;
- обмен между клиентом и сервером выполняется через HTTP в JSON;
- должны существовать все шесть CRUD-маршрутов: `GET` списка, `GET` одной записи, `POST`, `PUT`, `PATCH`, `DELETE`;
- сервер обязан валидировать данные и возвращать правильные коды `200`, `201`, `204`, `400`, `404`, `500`;
- некорректный JSON не должен приводить к падению сервера;
- идентификаторы после удаления не переиспользуются;
- клиент должен поддерживать просмотр, добавление, редактирование и удаление без перезагрузки страницы;
- на клиенте нужны подтверждение удаления, отображение ошибок, загрузки и пустого списка;
- код должен быть разделён на логические модули;
- нужен `README` с инструкцией запуска.

## 2. Согласованные решения

### Предметная область

Выбрана тема **«Смехдер» — шуточный аналог Tinder для текстовых анекдотов**.

Изначально обсуждался Tinder для мемов, но от картинок отказались, чтобы не создавать дополнительные обязанности по загрузке файлов, хранению изображений, обработке битых URL, разным пропорциям картинок и зависимости демонстрации от интернета.

Приложение имеет два основных пользовательских режима:

1. **Свайпы** — карточки анекдотов можно свайпать вправо («Ахах») или влево («Баян»).
2. **Анекдотека** — обычный интерфейс управления, через который доступен полный CRUD.

Свайпы являются дополнительной функцией и не заменяют обязательные CRUD-операции.

### Стек

Согласован следующий стек:

- клиент: React + TypeScript + Vite;
- сервер: Java 21 без Spring, фреймворк Javalin;
- JSON: Jackson;
- SQL-доступ: JDBI;
- база данных: PostgreSQL;
- миграции: Flyway;
- документация API: OpenAPI 3 + Swagger UI;
- запуск: Docker Compose;
- язык интерфейса: русский;
- стиль интерфейса: современный, аккуратный, адаптивный и слегка мемный.

Авторизация не предусмотрена: она отсутствует в ТЗ и необоснованно увеличила бы объём лабораторной. Лайки и дизлайки являются общей статистикой. Просмотренные в конкретном браузере карточки сохраняются в `localStorage`.

## 3. Модель данных

Основная сущность — `Joke`:

| Поле | Тип | Назначение |
|---|---|---|
| `id` | `long` | Идентификатор PostgreSQL `BIGSERIAL` |
| `text` | `string` | Текст анекдота, до 2000 символов |
| `category` | `string` | Категория, до 50 символов |
| `author` | `string` | Автор, до 100 символов |
| `publishedAt` | `date` | Дата публикации, не позднее текущей даты |
| `absurdityLevel` | `integer` | Уровень абсурда от 1 до 10 |
| `adult` | `boolean` | Возрастное ограничение |
| `likes` | `integer` | Количество реакций «Ахах» |
| `dislikes` | `integer` | Количество реакций «Баян» |
| `createdAt` | `datetime` | Дата создания записи сервером |

Модель покрывает строковый, числовой, логический типы и дату с запасом.

## 4. API

Реализованы обязательные маршруты:

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/jokes` | Получить все анекдоты |
| `GET` | `/api/jokes/{id}` | Получить один анекдот |
| `POST` | `/api/jokes` | Создать анекдот |
| `PUT` | `/api/jokes/{id}` | Полностью обновить анекдот |
| `PATCH` | `/api/jokes/{id}` | Частично обновить анекдот |
| `DELETE` | `/api/jokes/{id}` | Удалить анекдот |

Дополнительный маршрут:

- `POST /api/jokes/{id}/reaction` с JSON `{"reaction":"LIKE"}` или `{"reaction":"DISLIKE"}`.

Реакция увеличивает нужный счётчик атомарным SQL-запросом. Это безопаснее, чем передавать с клиента вычисленное новое значение счётчика.

Также реализованы:

- `GET /health`;
- `GET /openapi.json`;
- единый формат ошибок `{"error":"...","details":["..."]}`;
- серверная валидация;
- CORS для клиента;
- Swagger UI в разделе «API» клиентского приложения.

## 5. Что уже создано

### Корень проекта

- `docker-compose.yml` — PostgreSQL, API и frontend;
- `README.md` — инструкции запуска, описание стека и API;

### Сервер (`backend`)

Код разделён на слои:

- `controller/JokeController` — HTTP-слой;
- `service/JokeService` — прикладная логика;
- `repository/JokeRepository` — SQL через JDBI;

- `model`, `dto`, `exception`, `config` — модель, контракты и инфраструктура;
- `db/migration/V1__create_jokes.sql` — создание таблицы и шесть стартовых анекдотов;
- `openapi.json` — спецификация OpenAPI 3;
- `Dockerfile` и `pom.xml`.

### Клиент (`frontend`)

Созданы:

- `Library` со списком, поиском, редактированием и удалением;
- `JokeForm` для создания и редактирования;
- API-клиент на `fetch`;
- Swagger UI;
- состояния загрузки, ошибок и пустых списков;
- адаптивное оформление в `styles.css`;
- Dockerfile и nginx-конфигурация.

## 6. Текущее состояние

На 16 сентября 2026 года проект полностью собирается и запускается через
`docker compose up --build -d`. PostgreSQL healthy, API и frontend работают.

Исправлено:

- Javalin-код адаптирован под 7.2.3;
- из Dockerfile API удалён медленный `dependency:go-offline`, который скачивал
  большой набор ненужных зависимостей Maven-плагинов и занимал около 256 секунд;
- Docker-сборка Maven использует постоянный BuildKit-кэш `/root/.m2` и выводит
  прогресс; проверенная сборка заняла около 19 секунд с частично пустым кэшем и
  около 9 секунд с прогретым;
- Maven Shade объединяет `META-INF/services`, поэтому Flyway находит PostgreSQL
  database plugin внутри fat JAR;
- даты Jackson выдаются ISO-строками согласно frontend и OpenAPI, а не массивами
  и epoch timestamp;
- создан корректный `frontend/package-lock.json`, frontend использует `npm ci`;
- добавлены `.dockerignore` для backend и frontend.
- добавлена миграция `V2__add_more_jokes.sql` с 40 авторскими анекдотами;
  после применения в базе 46 записей в 9 категориях.

Реально проверены: health, OpenAPI, CORS, выдача стартовых данных, POST, GET,
PUT, PATCH, реакция, DELETE, 400 для невалидных полей и сломанного JSON, 404,
а также непереиспользование удалённого ID. Frontend через nginx отвечает 200.

## 8. Возможные места для дополнительной проверки

- Убедиться, что исключение Jackson при полностью сломанном JSON попадает в обработчик `JsonProcessingException`, а не оборачивается Javalin в другой тип. Если возвращается `500`, добавить обработчик фактического типа исключения.
- Проверить поддержку привязки `LocalDate` в используемой версии JDBI. При необходимости зарегистрировать Java Time plugin или передавать `java.sql.Date`.
- Проверить выдачу `openapi.json` через `getResourceAsStream`.
- Проверить совместимость `swagger-ui-react@5.21.0` с закреплённым React 18.
- Убедиться, что CORS-заголовки присутствуют для `http://localhost:5173`.
- При желании отказаться от внешнего импорта Google Fonts в CSS, чтобы интерфейс был полностью автономным без интернета. Сейчас при недоступности сети используется системный шрифт.

## 9. Важные ограничения и намерения

- Не добавлять изображения: решение перейти к текстовым анекдотам принято специально, чтобы не усложнять лабораторную.
- Не добавлять авторизацию без отдельного запроса пользователя.
- Не заменять PostgreSQL хранением в памяти или JSON-файле.
- Не убирать `PUT` или `PATCH`: для приёмки нужны оба маршрута.
- Сохранить разделение на свайпы и анекдотеку: именно анекдотека делает полный CRUD явно доступным из UI.
- Основной способ запуска — Docker Compose, но локальные команды также должны оставаться описанными в README.
